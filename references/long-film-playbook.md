# 长视频制作指南（30~60 分钟课程片）

> 结论先说：**一小时没问题。** 本流水线的每一环（渲染、缝合、配音、复检）都按「幕」解耦，
> 幕数只线性增加工作量，不改变任何方法。样板间 144s/11 幕，1 小时 ≈ 45~60 幕。

## 1. 产能与资源估算（按样板间实测外推）

| 项目 | 样板间 144s | 1 小时片（25×） | 说明 |
|---|---|---|---|
| 幕数 | 11 | 45~60 | 一幕 40~80s，一幕一个场景类 |
| 渲染机器时间 | ~25 min | **8~14 h** | ≈ 成片时长 × 8~20 倍；分章无人值守跑，一晚一章 |
| TTS 配音 | 免费，数分钟 | 免费，~30 min | edge-tts 按段缓存，重配只花改动量 |
| 混流/缝合 | <1 min | 数分钟 | ffmpeg 无损，逐章/整片均可 |
| 源码编写 | 3 文件/11 幕 | 12~18 文件/50 幕 | **一个主题文件一个章**，控制单文件规模 |

费用构成：全部本地计算 + 免费 TTS = **电费与机器时间**，无版权/云费用。

## 2. 章节化工程结构（超过 10 幕必用）

```
_proj-课程名/
├── 00-总纲.md                    # 课程大纲：章→幕清单→每幕讲什么（先写它！）
├── ch01-极限与连续/
│   ├── ch01_scenes.py           # 本章全部场景类（或每幕一个文件，均可）
│   ├── assets/                  # 本章专属素材
│   └── build/scenes.json
├── ch02-导数与微分/ ...
├── build/master_scenes.json     # 全片幕序清单（唯一事实来源）
├── work/                        # 配音配置、音频缓存、段落表
├── out/                         # 分章成片 + 母带 + 配音版
└── 交接文档.md                  # 断点续作（见 §6）
```

`build/master_scenes.json`（模板见 `assets/templates/scenes.template.json`）：

```json
{
  "project_dir": "/abs/path/_proj-课程名",
  "output_dir": "out/episodes",
  "master_name": "课程名_母带_1080P60.mp4",
  "scenes": [
    {"script": "ch00-coldopen/ch00_scenes.py", "scene": "Ch00_ColdOpen3D", "output": "000_片头.mp4"},
    {"script": "ch01-极限/ch01_scenes.py",     "scene": "Ch01_Intro",      "output": "010_第一章_开场.mp4"}
  ]
}
```

## 3. 渲染策略：分章增量，绝不整片重渲

```bash
# 首次：逐章渲染（每章一条命令，可 screen/tmux 挂机）
python scripts/build_film.py ch01/build/scenes.json
# 某幕改了只重渲那一幕（--only 接场景类名或输出文件名，可多个）
python scripts/build_film.py build/master_scenes.json --only Ch03_04_证明二
# 全部就绪后：只缝合不渲染（--no-render）
python scripts/build_film.py build/master_scenes.json --no-render
```

- manim 的 `media/` 缓存按源码文件哈希命中，未改的幕即使重跑也快；但仍建议配 `--only` 精确打击。
- **每章渲染完立即 verify + 抽帧过目**，不要攒到最后统一看——错误越早发现返工越小。

## 4. 配音策略：分章配音 → 无损合并

1. 每章独立 `work/chXX_dub_config.json`：段落的 `start/end` 用**本章局部时间**（从 0 起）。
2. 对每章成片跑 `dub_pipeline.py` → 得到 `chXX_配音版.mp4`（音画同步在章内闭环，问题不跨章传播）。
3. 全部章节完成后，写一个纯 concat 清单把各章**配音版**顺序无损缝合（音视频参数一致，`-c copy` 直拷）：

```bash
ffmpeg -f concat -safe 0 -i all_chapters.txt -c copy 课程全片_配音版_1080P60.mp4
```

4. 全片级 `verify_film.py` 终检：总时长 = Σ章节 ±1s（concat 有帧对齐余量），响度抽点加倍密度。

> 也可以把全片段落写进一个大 config 一次性混流（样板间 26 段即此法）；经验边界：**300 段以内**可行，
> 超过后 ffmpeg 滤镜图过大、单段改稿重排全片，收益转负。长片一律推荐分章。

## 5. 一致性控制（50 幕不跑样的关键）

- 常量与基类**逐字复用**样板间 `style-guide.md §4` 的代码块，禁止章与章之间出现两套字号/颜色/间距。
- 每章开头做一个「本章导航镜头」（title_bar + 章节号），与片头神殿同色系，观众始终知道自己在哪。
- 术语表：建 `00-总纲.md#术语表`，专有名词的中英文、符号写法全片唯一（比如 ξ 与 xi 二选一）。
- 片头/片尾神殿、章节转场复用样板间 3D 模式（style-guide §6），只换文案。

## 6. 断点续作：交接文档模板（每章渲染完更新一次）

```markdown
# 交接文档（更新于 <日期>）
## 已完成
- ch01 渲染+配音全绿（verify 通过 2026-XX-XX）；ch02 渲染完、配音进行到 §3
## 进行中
- ch02_03 段文案超长被管线标记 LONG，需删约 12 字
## 待办
- ch03 脚本未动笔；片头神殿文案待客户确认
## 避坑备忘（本章新增）
- （渲染/配音中踩的新坑写这里）
```

任何 agent 接手，读 `00-总纲.md` + `交接文档.md` 即可续作——样板间项目正是这样交付的。

## 7. 里程碑验收节奏

| 节点 | 动作 |
|---|---|
| 每幕烟测 | `-ql` + 抽帧（版式） |
| 每章渲染完 | verify 章成片 + 人眼过全章 |
| 每章配音完 | verify 音画 + 响度 |
| 全片缝合后 | verify 全片 + 首中尾探针 + 客户试看 5 分钟样带 |
| 交付 | 成片 + 段落表 + 配音稿 + 复检报告 |
